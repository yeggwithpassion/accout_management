异常处理

异常处理与事务回滚

业务失败

余额不足、持仓不足、账户冻结、身份不一致等错误不进入数据库变更阶段。

事务失败

数据库写入失败或唯一键冲突时回滚事务，避免保留半完成状态。

跨系统失败

交易管理系统超时或不可用时记录请求摘要，后续按账户号、订单号或流水号补偿。

安全异常

密码连续错误、越权访问、伪造 token 和高频请求会被拒绝，并保留安全审计记录。

ERR_001 余额不足 ERR_002 持仓不足 ERR_003 账户已冻结 ERR_009 权限不足 ERR_018 交易更新重复 ERR_019 结息重复或参数错误
错误响应仍使用 code / message / data 日志不明文记录密码、token 和证件号码

运行流程

业务请求处理流程

1. 提交请求 工作人员管理端或交易系统发起开户、挂失、存取款、交易更新等业务。
2. 三类校验 先做参数、权限和账户状态校验，失败时直接返回错误码，不修改数据库。
3. 事务更新 余额、冻结余额、持仓、账户状态和绑定关系放入同一事务处理。
4. 同步补偿 跨系统接口失败时回滚本地事务，或记录待补偿任务并按幂等键重试。

账户状态

正常、挂失冻结、违规冻结、预销户、已销户由账户状态管理统一控制，禁止重复冻结、重复销户。

交易联动

买入冻结、买入扣款、卖出回款和撤单解冻都写入资金流水，并与持仓变更保持一致。

年度结息

每年 6 月 30 日按可用余额和年利率计算利息，更新余额并生成“结息”资金流水。

审计追踪

开户、挂失、销户、修改密码、管理员查询和黑名单维护都写入操作日志。
