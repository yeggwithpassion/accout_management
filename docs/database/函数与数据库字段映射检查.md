# 函数与数据库字段映射检查

## 1. 说明

- 以 `D:\0x00zju资料合集\CS计算机类\FSE 软件工程基础\Database\DataBase.txt` 为准，它已经确认是当前**正确数据库设计**。
- 本文检查对象主要是设计报告中的：
  - `3.7.5 功能函数信息`
  - `3.7.3 外部接口`
  - `7.3.x 运行流程`
- 目标不是重做数据库，而是明确：**每个函数实际需要哪些数据库字段**，以及**报告里哪些地方和当前数据库不一致**。

## 2. 先给结论：报告中明显不一致的点

### 2.1 当前数据库里没有的表

- `blacklist`
  - 报告多处写了“黑名单维护”“blacklist.证件号码”。
  - 当前数据库设计里**没有 blacklist 表**。
  - 因此：
    - `checkBlacklist` 应被视为**外部接口/外部系统能力**；
    - 不能把它写成当前库内字段依赖。

- `freeze_record`
  - 报告在证券账户挂失、资金账户挂失、管理员冻结等地方多次写“写入 freeze_record”或“查询冻结历史”。
  - 当前数据库设计里**没有 freeze_record 表**。
  - 现有库里与冻结相关的只有：
    - `security_account.status`
    - `fund_account.status`
    - `fund_account.frozen_balance`（交易冻结资金）
    - `holding.frozen_quantity`（交易冻结持仓）
    - `operation_log.detail`（可记录冻结原因）

### 2.2 当前数据库里没有的字段

- `staff.role`
  - 报告在 `staffLogin`、`queryOperationLog`、运行流程里多次写“角色”。
  - 当前 `staff` 表只有：
    - `staff_id`
    - `username`
    - `password_hash`
    - `permission_level`
    - `status`
    - `created_at`
  - 所以权限判断应基于 `permission_level`，不是 `role`。

- `operation_log.ip_address`
  - 报告写到日志返回“IP地址”。
  - 当前 `operation_log` 表**没有 IP 字段**。
  - 如果一定要保存 IP，只能：
    - 追加表字段；
    - 或临时写入 `operation_log.detail`。

### 2.3 报告里的“冻结”语义混用了两套字段

- `fund_account.frozen_balance` 在当前数据库设计里是**交易冻结资金**，典型场景是“买入委托冻结”。
- `holding.frozen_quantity` 在当前数据库设计里是**交易冻结持仓**，典型场景是“卖出委托冻结”。
- 因此：
  - 账户挂失/违规冻结，核心应依赖 `status`；
  - 不应该直接把“挂失冻结”简单等同为转移到 `frozen_balance` 或批量写 `holding.frozen_quantity`，除非你们准备额外定义业务规则。

### 2.4 一些能力本来就不在当前数据库内

- “是否存在未成交委托”
  - 当前数据库没有委托表。
  - `closeFundAccount`、部分强制销户逻辑只能依赖**外部交易系统查询**。

- “股票代码是否合法”
  - 当前数据库没有股票基础信息表。
  - `holding.stock_code` 只能作为交易系统传入的业务主键使用。

## 5. 建议你们直接改报告的几句话

- 把“`blacklist.证件号码`”改成“通过外部黑名单校验接口 `checkBlacklist` 完成，非当前数据库内表”。
- 把所有“写入 `freeze_record`”“返回冻结历史”改成“写入 `operation_log.detail` 记录冻结原因；当前数据库无独立冻结历史表”。
- 把所有“`staff.role`”改成“`staff.permission_level`”。
- 把“操作日志返回 IP 地址”改成“当前表无独立 IP 字段，如需记录需扩展表结构或写入 `detail`”。
- 把“资金账户挂失时冻结资金余额”改成“资金账户挂失主要通过 `fund_account.status='挂失冻结'` 控制；`frozen_balance` 主要用于交易冻结”。
- 把“证券账户挂失时冻结持仓”改成“证券账户挂失主要通过 `security_account.status='挂失冻结'` 和外部交易限制控制；`holding.frozen_quantity` 主要用于委托冻结”。
- 把“修改后的所有信息”改成“仅修改允许更新字段”，尤其是：
  - 投资者：`phone`、`address`、`occupation`、`education` 等；
  - 工作人员：`password_hash`、`permission_level`、`status`。

## 6. 一句话总结

当前正确数据库可以完整支撑“开户、绑定、存取款、挂失、补办、销户、持仓更新、流水记录、日志审计”这些核心业务；设计报告的主要问题不是表不够用，而是**把外部能力写成了本地表、把交易冻结和挂失冻结混在了一起、并引用了几个当前库里根本不存在的表/字段**。
