# 数据库具体设计与对外接口说明

## 1. 说明

本文以 [DataBase.txt](</D:\0x00zju资料合集\CS计算机类\FSE 软件工程基础\Database\DataBase.txt>) 为准，整理当前版本真正需要实现的数据库设计和对外接口。

当前版本的明确边界如下：

- 不维护 `blacklist` 表，黑名单不属于当前数据库设计范围。
- 不维护 `freeze_record` 表，冻结历史不单独建表。
- 不做 RBAC，`staff` 只有普通工作人员，不区分角色。
- 不记录 IP 地址，因此 `operation_log` 不包含 IP 字段。
- 账户冻结判断以 `status` 为核心。
- 只有在账户状态允许的前提下，才进一步检查交易冻结资金或交易冻结持仓。

## 2. 设计原则

- 除持仓表外，其余核心表均采用逻辑删除，不执行物理删除。
- 密码字段全部保存加盐哈希，不保存明文。
- 金额统一使用 `DECIMAL(15,2)`。
- 涉及余额、冻结金额、持仓数量、账户状态联动的操作必须放在同一事务中。
- 所有关键业务操作需要记录操作日志或资金流水。

## 3. 数据库总体结构

当前数据库共 7 张核心表：

1. `investor`：投资者信息
2. `security_account`：证券账户
3. `fund_account`：资金账户
4. `fund_transaction_log`：资金流水
5. `staff`：工作人员
6. `holding`：证券持仓
7. `operation_log`：操作日志

核心关系如下：

- 一个 `investor` 可以关联一个或多个 `security_account`
- 一个 `security_account` 至多绑定一个 `fund_account`
- 一个 `fund_account` 只绑定一个 `security_account`
- 一个 `security_account` 可以关联多条 `holding`
- 一个 `fund_account` 可以关联多条 `fund_transaction_log`
- 一个 `staff` 可以关联多条 `operation_log`

## 4. 表设计

## 4.1 投资者表 `investor`

用途：保存个人投资者或法人投资者的基础身份信息。

### 字段

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `investor_id` | `INT` | PK, AUTO_INCREMENT | 投资者内部编号 |
| `type` | `ENUM` | NOT NULL | `个人` / `法人` |
| `name` | `VARCHAR(100)` | NOT NULL | 姓名或企业名称 |
| `id_type` | `VARCHAR(20)` | NOT NULL | 证件类型 |
| `id_number` | `VARCHAR(50)` | NOT NULL, UNIQUE | 证件号码 |
| `phone` | `VARCHAR(20)` | NULL | 联系电话 |
| `address` | `VARCHAR(200)` | NULL | 联系地址 |
| `occupation` | `VARCHAR(50)` | NULL | 职业，个人使用 |
| `education` | `VARCHAR(50)` | NULL | 学历，个人使用 |
| `legal_number` | `VARCHAR(20)` | NULL | 法人注册登记号 |
| `business_license` | `VARCHAR(20)` | NULL | 营业执照号码 |
| `authorize_name` | `VARCHAR(20)` | NULL | 授权人有效身份证号 |
| `authorize_phone` | `VARCHAR(20)` | NULL | 授权人联系电话 |
| `authorize_address` | `VARCHAR(100)` | NULL | 授权人地址 |
| `executor_name` | `VARCHAR(50)` | NULL | 法人授权执行人姓名 |
| `agent_name` | `VARCHAR(100)` | NULL | 代办人姓名 |
| `agent_id_number` | `VARCHAR(50)` | NULL | 代办人证件号码 |
| `created_at` | `DATETIME` | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |

### 约束与说明

- `id_number` 全局唯一，用于防重复开户和身份校验。
- `id_type`、`id_number` 默认不允许在普通信息修改中变更。
- 法人扩展字段在个人投资者场景下可为空。

## 4.2 证券账户表 `security_account`

用途：保存证券账户生命周期状态及其与投资者、资金账户的关联。

### 字段

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `sec_acc_no` | `VARCHAR(20)` | PK | 证券账户号 |
| `investor_id` | `INT` | FK, NOT NULL | 关联 `investor.investor_id` |
| `status` | `ENUM` | NOT NULL | `正常` / `挂失冻结` / `违规冻结` / `预销户` / `已销户` |
| `open_date` | `DATE` | NOT NULL | 开户日期 |
| `linked_fund_acc` | `VARCHAR(20)` | FK, UNIQUE, NULL | 绑定资金账户号 |

### 约束与说明

- 一个证券账户至多绑定一个资金账户。
- `status` 是账户是否可继续办理业务的第一判断条件。
- `linked_fund_acc` 用于和 `fund_account` 建立一对一绑定。

## 4.3 资金账户表 `fund_account`

用途：保存资金账户余额、密码、状态和与证券账户的绑定关系。

### 字段

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `fund_acc_no` | `VARCHAR(20)` | PK | 资金账户号 |
| `sec_acc_no` | `VARCHAR(20)` | FK, NOT NULL, UNIQUE | 绑定证券账户号 |
| `trade_password` | `VARCHAR(128)` | NOT NULL | 交易密码哈希 |
| `withdraw_password` | `VARCHAR(128)` | NOT NULL | 取款密码哈希 |
| `available_balance` | `DECIMAL(15,2)` | NOT NULL, DEFAULT 0.00 | 可用余额 |
| `frozen_balance` | `DECIMAL(15,2)` | NOT NULL, DEFAULT 0.00 | 交易冻结余额 |
| `currency` | `CHAR(3)` | NOT NULL, DEFAULT `CNY` | 币种 |
| `status` | `ENUM` | NOT NULL | `正常` / `挂失冻结` / `违规冻结` / `已销户` |
| `open_date` | `DATE` | NOT NULL | 开户日期 |
| `last_interest_date` | `DATE` | NULL | 上次结息日 |
| `annual_interest_rate` | `DECIMAL(5,4)` | NOT NULL, DEFAULT 0.0035 | 年利率 |

### 约束与说明

- 一个资金账户只对应一个证券账户。
- `status` 先决定账户是否可操作。
- `frozen_balance` 只表示交易冻结资金，不单独表示挂失冻结历史。

## 4.4 资金流水表 `fund_transaction_log`

用途：记录资金账户的每次资金变动结果。

### 字段

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `log_id` | `BIGINT` | PK, AUTO_INCREMENT | 流水编号 |
| `fund_acc_no` | `VARCHAR(20)` | FK, NOT NULL | 资金账户号 |
| `txn_type` | `ENUM` | NOT NULL | `存款` / `取款` / `买入冻结` / `买入扣款` / `卖出回款` / `撤单解冻` / `结息` |
| `amount` | `DECIMAL(15,2)` | NOT NULL | 变动金额 |
| `available_after` | `DECIMAL(15,2)` | NOT NULL | 变动后可用余额 |
| `frozen_after` | `DECIMAL(15,2)` | NOT NULL | 变动后冻结余额 |
| `ref_order_id` | `VARCHAR(50)` | NULL | 关联订单号 |
| `operator_id` | `INT` | FK, NULL | 人工操作工作人员编号 |
| `txn_time` | `DATETIME` | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 交易时间 |

### 约束与说明

- 该表只允许 `INSERT` 和 `SELECT`。
- 交易相关接口可以通过 `ref_order_id` 做幂等控制。

## 4.6 持仓表 `holding`

用途：保存证券账户对各股票的当前持仓情况。

### 字段

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `holding_id` | `BIGINT` | PK, AUTO_INCREMENT | 持仓编号 |
| `sec_acc_no` | `VARCHAR(20)` | FK, NOT NULL | 证券账户号 |
| `stock_code` | `VARCHAR(10)` | NOT NULL | 股票代码 |
| `quantity` | `INT` | NOT NULL, DEFAULT 0 | 持有股数 |
| `frozen_quantity` | `INT` | NOT NULL, DEFAULT 0 | 交易冻结股数 |
| `avg_cost` | `DECIMAL(15,4)` | NULL | 移动平均成本 |
| `updated_at` | `DATETIME` | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 最后更新时间 |

### 约束与说明

- `frozen_quantity` 只表示交易冻结持仓，不单独表示挂失冻结。
- 可卖数量为计算值：`quantity - frozen_quantity`。
- 当 `quantity = 0` 且 `frozen_quantity = 0` 时，可选择保留或删除该记录。

## 5. 状态与冻结规则

### 5.1 账户状态优先

对证券账户或资金账户执行任何关键操作前，优先检查 `status`。

- 若 `status` 为 `挂失冻结`、`违规冻结`、`已销户`，通常直接拒绝普通业务。
- 若 `status` 为 `预销户`，仅允许继续完成销户相关处理。
- 只有 `status = 正常` 时，才进入下一步业务校验。

### 5.2 交易冻结是第二层校验

在账户状态允许后，再检查交易冻结量：

- 资金业务检查 `fund_account.frozen_balance`
- 持仓业务检查 `holding.frozen_quantity`

例如：

- 取款时先看 `fund_account.status` 是否正常，再看 `available_balance` 是否足够。
- 卖出时先看 `security_account.status` 是否正常，再看 `quantity - frozen_quantity` 是否足够。

### 5.3 当前版本不单独维护冻结历史

当前版本只维护最终状态和当前冻结量：

- 账户冻结看 `status`
- 交易冻结资金看 `frozen_balance`
- 交易冻结持仓看 `frozen_quantity`

如果需要记录人工冻结原因或补办说明，可写入 `operation_log.detail`。

## 6. 核心业务与数据库落点

## 6.1 证券账户开户

- 校验 `investor.id_number` 是否已存在
- 新增或复用 `investor`
- 写入 `security_account`
- 记录 `operation_log`

## 6.2 证券账户挂失

- 校验 `security_account.status`
- 更新 `security_account.status='挂失冻结'`
- 记录 `operation_log`

## 6.3 证券账户补办

- 校验原账户 `status='挂失冻结'`
- 新建证券账户
- 迁移 `holding.sec_acc_no`
- 更新关联 `fund_account.sec_acc_no`
- 更新新旧 `security_account`
- 记录 `operation_log`

## 6.4 证券账户销户

- 校验 `security_account.status`
- 检查 `holding.quantity`
- 若仍有持仓，更新为 `预销户`
- 若无持仓，解除与 `fund_account` 的绑定并置 `已销户`
- 记录 `operation_log`

## 6.5 资金账户开户与绑定

- 校验 `security_account.status='正常'`
- 联查 `investor.id_number` 做身份核验
- 写入 `fund_account`
- 更新 `security_account.linked_fund_acc`
- 记录 `operation_log`

## 6.6 存款

- 校验 `fund_account.status='正常'`
- 增加 `available_balance`
- 写入 `fund_transaction_log`

## 6.7 取款

- 校验 `fund_account.status='正常'`
- 校验 `withdraw_password`
- 校验 `available_balance`
- 扣减 `available_balance`
- 写入 `fund_transaction_log`

## 6.8 资金账户挂失

- 校验 `fund_account.status`
- 更新 `fund_account.status='挂失冻结'`
- 记录 `operation_log`

## 6.9 资金账户补办

- 校验原账户 `status='挂失冻结'`
- 新建资金账户并复制余额、币种、利率等信息
- 更新旧账户状态
- 更新 `security_account.linked_fund_acc`
- 记录 `operation_log`

## 6.10 资金账户销户

- 校验 `status='正常'`
- 校验 `available_balance=0`
- 校验 `frozen_balance=0`
- 解除与 `security_account` 的绑定
- 更新为 `已销户`
- 记录 `operation_log`

## 6.11 交易更新

- 资金侧通过 `fund_account` 和 `fund_transaction_log` 维护
- 持仓侧通过 `holding` 维护
- 关联订单号通过 `fund_transaction_log.ref_order_id` 做幂等控制

## 6.12 年度结息

- 读取 `fund_account.available_balance`
- 读取 `last_interest_date`、`annual_interest_rate`
- 更新 `available_balance`
- 更新 `last_interest_date`
- 写入 `fund_transaction_log`

## 8. 当前版本不纳入数据库的内容

- 黑名单表
- 冻结记录表
- 工作人员角色体系
- IP 审计字段
- 委托单表
- 股票基础信息表

这些内容如果后续需要扩展，可以在下一版本单独补充，不影响当前 7 张核心表完成账户业务主流程。

## 9. 总结

当前版本数据库设计的核心非常明确：

- 身份信息由 `investor` 管
- 证券账户状态由 `security_account` 管
- 资金账户余额与状态由 `fund_account` 管
- 资金变动由 `fund_transaction_log` 管
- 持仓数量与交易冻结由 `holding` 管
- 人工关键操作由 `operation_log` 管

对外接口也围绕这 7 张表展开，不再依赖黑名单表、冻结记录表、角色体系或 IP 审计字段。冻结判断的统一规则是：**先看账户 `status`，再看交易冻结字段。**
